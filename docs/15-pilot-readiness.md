# ۱۵ — گزارش آمادگی پایلوت

شرط عبور از پایلوت (بخش ۲۴ سند کارفرما) — وضعیت واقعی هر عنصر:

| شرط | وضعیت | شواهد |
| --- | --- | --- |
| صحت دفترکل | **آزموده** | ۲۸/۲۸ آزمون روی PG 16.2؛ توازن DEFERRABLE در DB؛ Property tests؛ قیدهای nonneg؛ reconciliation job؛ trigger بی‌ردپا |
| تحویل‌پذیری پاداش | **آزموده (مسیرهای اصلی)** | delivered/cancelled/failed/unknown/expired در آزمون‌ها و Seed؛ TTL sweeper؛ reconciliation بدون استرداد خودکار |
| فعال‌بودن اعتراض | **آزموده** | گردش ثبت→مرجع مستقل→پذیرش→سند جبرانی→بازمحاسبهٔ سطح (TST-13)؛ SLA برچسب تأخیر |
| کنترل دسترسی معتبر | **آزموده** | RBAC/Scope/مالکیت + جداسازی دانشگاه + Provider minimal + tech-admin بدون دادهٔ آموزشی |
| نبود آسیب آموزشی/تبعیض تأییدشده | **نیازمند مشاهدهٔ میدانی** | طراحی: بدون رتبه‌بندی عمومی، بدون برچسب‌گذاری، شاخص «فشار انگیزشی/خروج/شکایت» در Analytics؛ سنجش واقعی پس از پایلوت |

## پیش‌نیازهای شروع پایلوت (مسدودکننده‌ها)
1. پاسخ کارفرما به Q1..Q4 (هویت OIDC، LMS، اعداد سیاست مصوب، ارائه‌دهندگان) — تا آن زمان بهره‌برداری واقعی قفل است (`REQUIRE_POLICY_SIGNOFF`).
2. استقرار Production با TLS، MFA و `ENABLE_SIMULATORS=false`.
3. اجرای Playwright/axe و Load test در CI واقعی.
4. آزمون Backup/Restore واقعی و ثبت RPO/RTO مصوب.

## آنچه در پایلوت پایش می‌شود
- مغایرت دفترکل (باید صفر باشد)، شکست رزرو/تحویل، تأخیر SLA پرونده‌ها
- خروج/لغو اعلان/شکایت از فشار انگیزشی (ANA-01)
- توزیع فرصت کسب امتیاز بین گروه‌ها (انصاف)

**نتیجه:** سامانه از نظر فنی برای پایلوت کنترل‌شده آماده است؛ شروع بهره‌برداری واقعی مشروط به ۴ پیش‌نیاز بالا است.
