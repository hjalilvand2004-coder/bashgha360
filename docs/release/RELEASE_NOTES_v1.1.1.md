# نسخهٔ ۱٫۱٫۱ — اصلاح اجرای نسخهٔ قابل‌حمل ویندوز (v1.1.1 Hotfix)

تاریخ: ۱۴۰۴/۰۸/۲۴ (2026-11-15)

## ایراد گزارش‌شده

```
runtime\python\python.exe: Error while finding module specification for 'app.portable'
(ModuleNotFoundError: No module named 'app')
```

این خطا حتی پس از اصلاح v1.1.0 باقی مانده بود.

## علت ریشه‌ای

پایتونِ جاسازی‌شدهٔ رسمی ویندوز (Embeddable) با فایل `python312._pth` در حالت
**isolated** اجرا می‌شود؛ در این حالت:

- متغیر محیطی `PYTHONPATH` **کاملاً نادیده گرفته می‌شود** (تنظیم آن در
  start.bat بی‌اثر بود)؛
- مسیر `.` داخل `._pth` به **پوشهٔ python.exe** اشاره می‌کند، نه ریشهٔ بسته؛

در نتیجه پکیج `app/` که کنار `start.bat` قرار داشت هرگز وارد `sys.path`
نمی‌شد. آزمون‌های قبلی روی لینوکس این را نشان نمی‌دادند (پایتون لینوکس عادی
است و `python -m` شاخهٔ جاری را اضافه می‌کند).

## اصلاحات (سه لایهٔ مستقل — هر یک به‌تنهایی کافی است)

1. `python312._pth` اکنون ریشهٔ بسته را هم دارد (`..\..`)؛
2. یک نسخه از پکیج `app` داخل `runtime\python\Lib\site-packages\app` قرار
   گرفت — مستقل از هر رفتار مسیری، import تضمین می‌شود؛
3. `start.bat` ریشهٔ بسته را با `CLUB360_BASE=%~dp0` به برنامه می‌دهد تا
   `data/`، `web/` و `.env` همیشه درست resolve شوند (با وجود محل فیزیکی app).

## بررسی صحت

- راستی‌آزمایی ساختاری بسته: `_pth` شامل `..\..`، وجود
  `site-packages\app\portable.py`، وجود `CLUB360_BASE` در start.bat؛
- بسته‌بودن importها در runtime جاسازی‌شده؛
- بوت واقعی بستهٔ لینوکس (healthz، SPA، SSO status، ورود محلی) — سبز؛
- 36/36 آزمون backend روی PostgreSQL واقعی — سبز.

«ریشهٔ بسته» در پنجرهٔ سرور مسیر واقعی مورداستفاده را نشان می‌دهد.
