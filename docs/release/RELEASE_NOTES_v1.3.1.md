# نسخهٔ ۱٫۳٫۱ — هات‌فیکس نسخهٔ قابل‌حمل ویندوز: قرنطینهٔ رویداد و کرش seed (v1.3.1)

تاریخ: ۱۴۰۵/۰۹/۰۱ (2026-11-22)

## ایراد گزارش‌شده (بستهٔ v1.3.0 ویندوز)

```
WARN: inbox lms-simulator:ev-att-000:r1 quarantined: 'No time zone found with key Asia/Tehran'
… (همهٔ رویدادهای نمونه)
app.core.errors.InsufficientPoints: امتیاز قابل مصرف کافی نیست.
Server stopped.
```

## علت ریشه‌ای

پایتونِ embeddable ویندوز (برخلاف لینوکس) دیتابیس IANA timezone ندارد؛ بدون پکیج
`tzdata` هر `ZoneInfo("Asia/Tehran")` می‌شکند:

1. پردازش رویدادهای LMS هنگام seed شکست می‌خورد → همهٔ رویدادها **قرنطینه** می‌شوند؛
2. امتیازهای مرتبط هرگز واریز نمی‌شود؛
3. گام نمایشی seed («درخواست پاداش نمونه») با `InsufficientPoints` کرش می‌کند و
   بسته اصلاً بوت نمی‌شود.

روی لینوکس و در CI این اتفاق نمی‌افتاد (دیتابیس timezone سیستم موجود است) —
به همین دلیل ساخت و آزمون v1.3.0 سبز بود ولی اجرای ویندوز شکست خورد.

## اصلاحات (سه لایهٔ مستقل)

1. **ریشهٔ اصلی** — پکیج `tzdata==2025.2` به وابستگی‌های backend و به ویل‌های
   بستهٔ قابل‌حمل اضافه شد؛ `ZoneInfo` روی ویندوز همیشه کار می‌کند و رویدادها
   پردازش می‌شوند.
2. **مقاوم‌سازی seed** — سه گام پاداش نمایشی اکنون مستقل و غیرمرگبارند: هر خطا
   فقط `WARN` و ادامهٔ seed (بوت برنامه هرگز به‌دلیل دیتای نمایشی بسته نمی‌شود).
   داده‌های پایه (ارائه‌دهنده/پاداش‌ها) قبل از این گام‌ها commit می‌شوند تا
   rollbackِ داخل except به بخش‌های بعدی seed آسیب نزند.
3. **ابزار بسته‌بندی** — نام فایل بسته از تگ گیت خوانده می‌شود؛ `SyntaxWarning`
   داکیومنت هم اصلاح شد.

## راستی‌آزمایی

- **۴۸/۴۸ آزمون** روی PostgreSQL واقعی — سبز (`backend/TEST_RESULTS.md`).

## مهم — ارتقا از v1.3.0 ویندوز

اگر قبلاً بستهٔ v1.3.0 ویندوز را اجرا کرده‌اید، پوشهٔ `data` کنار `start.bat`
را **حذف کنید** و دوباره `start.bat` بزنید تا seed تمیز از نو اجرا شود. دیتای
موجودِ نسخهٔ خراب نیمه‌کاره است (رویدادهای قرنطینه‌شده بدون tzdata قابل بازیابی
نیستند) و `_prepare_db` به‌دلیل وجود کاربران، seed را تکرار نمی‌کند.

روی لینوکس و استقرار داکر نیازی به هیچ اقدامی نیست.
